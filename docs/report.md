# Итоговый отчёт

## Результат

Играбельная конфигурация не найдена. Один вход в мир в Caffe 9.7 подтверждён сообщением об успешном входе и наблюдениями пользователя, но управление и корректный игровой процесс не были подтверждены. Позже повторить даже этот частичный результат стабильно не удалось.

## Окружение

- CachyOS / Arch Linux, Hyprland с Lua-конфигурацией, Xwayland.
- NVIDIA GeForce RTX 4060 Laptop GPU.
- Экран ноутбука 1600×1000 и внешний монитор 1920×1080.
- Накопитель NVMe; подключённая USB-флешка определялась с размером 0 B. Это наблюдение, а не доказательство причины сбоя.
- Faugus Launcher Flatpak, UMU 1.4.4, GE-Proton 11-11; отдельно Bottles Caffe 9.7 в 32-битном префиксе.
- Финальный эксперимент: PortProton Flatpak 1.7.5, scripts 2481, отдельный префикс PROVINCE, GE-Proton 11-11 и DXVK 2.6.2 (Stable).

Это сведения о проверенной системе, а не рекомендуемые минимальные требования. Для других дистрибутивов результат не установлен.

## Проведённые проверки

| Вариант | Изменения | Наблюдение |
| --- | --- | --- |
| GE-Proton / UMU | Официальный лаунчер, VC++ x86/x64, шрифты | Лаунчер загружал игру; клиент зависал на подключении |
| Дополнительная диагностика | Загрузка DLL и исключения Wine | Встречались обработанные исключения в netc.dll; непосредственная причина зависания не доказана |
| Caffe 9.7 win32 | Отдельный префикс, VC++ x86, шрифты, пути MTA в реестре и каталоги ProgramData | Клиент дошёл до входа на сервер |
| Графические настройки Caffe | Full HD, затем оконный режим, лимит 60 FPS, отключение GPU для браузера | Первое успешное подключение сопровождалось мерцанием и неполным интерфейсом; устойчивого улучшения не подтверждено |
| Проверка serial-validation | Нативный сервер MTA 1.6 запускался от root и завершался | Повторные клиентские запуски продолжали выдавать ошибку |
| Сеть без VPN | Пользователь отключал VPN перед запуском, маршрут фиксировался в журнале | Ошибки сохранялись; сводить все сбои к VPN оснований нет |
| PortProton по подходу из видео | Новый префикс, официальный установщик, компоненты по сообщениям пользователя, GE-Proton и Stable DXVK | Лаунчер открывался; клиент прекращал запуск до подключения |

## Хронология ключевых наблюдений

Время ниже — местное, UTC+3; `report.log` MTA писал время на три часа раньше.

- В ночь на 7 ноября, примерно 00:06–00:17, Caffe 9.7 позволил войти на сервер. В журнале около 00:16:33 было сообщение об успешном входе. Пользователь видел радар и часть интерфейса, но сообщал о сильном мерцании и невозможности играть.
- После изменения графических параметров последующие попытки сопровождались `serial-validation`; возвращение подробного логирования это не исправило. Связь между настройками графики и проверкой серийного номера не доказана.
- Финальные попытки PortProton около 00:48–00:49 завершались на ранней инициализации. MTA каждый раз доходил до чтения русской локализации; свежего игрового `console.log` не появилось.

## Ошибки и их значение

### libwow64.dll и ожидание потока

В исходном окружении встречались `Failed to load ... libwow64.dll Error 126` и `WaitForSingleObject ... 4000ms`. Проверка файлов лаунчером при этом показывала отсутствие необходимых обновлений. Не установлено, является ли DLL обязательной для этого режима, поэтому случайные DLL из сторонних источников не использовались.

### Проверка серийного номера

Caffe после частичного успеха сообщал `There was a problem validating your serial`. В других попытках встречались CD16 / AckTimeout. Выполненная рекомендация с нативным сервером MTA от root не дала устойчивого результата.

Проверялись доступность UDisks2 из Flatpak и запросы WMI о дисках. В трассировке встречались ошибки открытия устройств NVMe. Эти данные не позволяют уверенно заключить, что виноваты диск, Flatpak или античит.

### Мерцание и интерфейс

Журнал фиксировал Full HD и повторные сбросы графического устройства, в том числе `Failed to get xinerama fullscreen monitor indices`. Оконный режим был разумной проверяемой гипотезой, но исправление мерцания не подтверждено: последующие запуски упирались в другие ошибки.

Ошибки ресурсов интерфейса и браузера сопровождали неполный игровой экран. Какая из них первична, не установлено.

### Финальный PortProton

Последние журналы фиксировали:

```text
Localization: .../ru_RU/client.pot:3442: error: expected empty line: msgstr "Онлайн"
HTTP Failed request ... Code: 28
```

Файл локализации заканчивался без завершающего перевода строки. Совпадение последней записи с завершением клиента не доказывает, что именно локализация вызвала сбой. `Code: 28` означает тайм-аут запроса лаунчера; маршруты в этих попытках шли напрямую через Wi-Fi без VPN.

Подробное логирование Wine в финальном окружении было выключено (`WINEDEBUG=-all`), поэтому непосредственная причина завершения по сохранённым данным не определена. Ошибки serial-validation в этих последних запусках не зарегистрированы: клиент мог просто не дойти до соответствующего этапа.

## Компоненты и шрифты

В исходном окружении установка VC++ завершалась успешно, а веб-установщик DirectX выдавал `Sections are not initialized`. Загрузки .NET в ранних попытках прерывались. Сам лаунчер содержит нативные модули и CEF; отсутствие .NET не было доказано причиной клиентского зависания.

В Caffe добавлялись Core Fonts, Tahoma и Microsoft Sans Serif. В PortProton пользователь сообщил об установке предложенных компонентов; индивидуальные версии и коды завершения каждого пакета отдельно не сверялись. Перенос файлов игры в новый префикс не переносил автоматически все настройки и компоненты старого окружения.

## Вывод

Работоспособность лаунчера, загрузка игры и даже разовый вход не равны подтверждённой совместимости. Для публикации рабочего установщика нужны повторяемый вход, управление, корректная отрисовка и повторный запуск. Эти условия не выполнены. Исследование остановлено без удаления локальных данных.
