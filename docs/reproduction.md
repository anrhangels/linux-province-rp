# Повторение эксперимента

Это протокол исследования для опытного пользователя. Он не гарантирует запуск игры и не заменяет официальный установщик.

## Порядок

1. Запишите ОС, драйвер, GPU, композитор, мониторы, версию лаунчера и дату. Сохраните собственный установщик из официального источника.
2. Подготовьте отдельный префикс для каждого варианта. Не запускайте разные Wine одновременно в одном префиксе и не используйте рабочие окружения других игр.
3. Проверяйте по очереди установку лаунчера, его обновление, проверку файлов, появление меню игры, подключение, вход и управление. На каждом этапе сохраняйте результат.
4. VPN в проверенной сети мешал Province. Сравнивайте результаты с записанным маршрутом на момент запуска. Подключение VPN после выхода, чтобы отправить сообщение, не описывает маршрут предыдущей игровой сессии.
5. Для нового опыта сначала используйте настройки по умолчанию. Меняйте одну переменную за раз и сохраняйте предыдущую конфигурацию.

## Испытанные варианты

### Faugus / UMU

GE-Proton 11-11 и UMU 1.4.4 запускались через Flatpak Faugus. Отдельный префикс содержал официальный лаунчер, VC++ и шрифты. Этот вариант зависал при подключении.

### Caffe 9.7 win32

Использовалась сборка [Bottles Caffe 9.7](https://github.com/bottlesdevs/wine/releases/tag/caffe-9.7) в отдельном `WINEARCH=win32` префиксе. Она запускалась через контейнерное окружение Steam Runtime, поскольку на хосте не было нужного 32-битного загрузчика. Простая замена Wine в существующем 64-битном префиксе этому опыту не эквивалентна.

Для перенесённой игры потребовались корректные пути GTA и MTA в реестре и доступный для записи каталог `C:\ProgramData\MTA San Andreas All\Common`. Универсальный скрипт для этого варианта не публикуется: стабильного результата нет.

### PortProton

Проверялся [PortProton из Flathub](https://flathub.org/en/apps/ru.linux_gaming.PortProton). Для установки самого приложения использовалось:

```bash
flatpak install --user flathub ru.linux_gaming.PortProton
```

Flathub должен быть предварительно подключён. Эта команда устанавливает PortProton, а не рабочую Провинцию.

После первичной настройки через PortProton открывался официальный установщик Province. Создавался отдельный префикс `PROVINCE`. Для установщика и установленного лаунчера выбирались один и тот же префикс, GE-Proton 11-11 и DXVK Stable 2.6.2. Компоненты устанавливались через их официальные окна; по видео веб-установщик DirectX предлагалось пропустить.

Установленный лаунчер находился в `C:\Program Files (x86)\Province Launcher\Launcher.exe`, файлы игры — в `C:\Province Games`. Копировалась отдельная папка игры, а не общий префикс. Версия Proton в видео 2025 года не была точно установлена; финальный эксперимент не является его побайтовым воспроизведением.

Зеркала загрузок PortProton возвращали ошибки соединения. После выбора GitHub компоненты скачались и прошли проверку контрольных сумм. Это исправило загрузку PortProton, но не подтвердило запуск игры.

## Где искать журналы

Пути ниже находятся внутри выбранного префикса:

```text
drive_c/ProgramData/MTA San Andreas All/1.6/report.log
drive_c/Province Games/MTA/logs/logfile.txt
drive_c/Province Games/MTA/logs/console.log
drive_c/Province Games/MTA/logs/clientscript.log
drive_c/users/<пользователь>/AppData/Local/Province Games/Logs/<дата>/
```

Имена некоторых файлов зависят от версии клиента. В PortProton из Flatpak префиксы в испытанном окружении лежали в:

```text
~/.var/app/ru.linux_gaming.PortProton/data/prefixes/
```

Всегда сверяйте время изменения: при копировании игры вместе с ней могут перенестись старые логи, которые не относятся к новому запуску. Запишите часовой пояс; `report.log` в наших опытах использовал UTC.

В PortProton можно выбрать **«Создать лог»**. Перед публикацией удалите никнеймы, токены, пути с личными именами и аппаратные идентификаторы. Полные журналы в этот репозиторий не включены.
